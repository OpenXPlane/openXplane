# Verifying ports against the original machine code

Date: 2026-10-06. The reference and SHA256 are in [BASELINE.md](BASELINE.md).

Until now the research notes compared the ports with the disassembly and with synthetic tests only; the
original was never run. `tools/emulate_xp.py` changes that for isolated functions: it maps the sections of
`X-Plane.exe` at their virtual addresses in the Unicorn CPU emulator, builds the data a function expects in a
scratch heap, and executes the original instructions. X-Plane itself is not started and no engine state exists
beyond what a test writes into memory.

## How it works

- Windows x64 calling convention: integer arguments in RCX, RDX, R8, R9; float arguments in XMM0-XMM3 by
  position; the fifth and later arguments on the stack after 32 bytes of shadow space (the fifth is at
  `0x20(%rsp)` at the call, `0x28(%rsp)` inside the callee); results in RAX/XMM0.
- Callees that need engine state can be replaced by Python stubs (`Emulator.stubs`); the functions verified so
  far need none.
- Test data is synthetic. Airfoil tables and the noise table are generated by formulas that both the Python
  generator and the Rust test evaluate identically, so no original airfoil file is involved.
- `tools/gen_profile_vectors.py` runs the function on random inputs and writes the output bit patterns to
  `tests/data/profile_stage.txt`; `tests/original_vectors.rs` recomputes each case with the Rust port and
  requires identical bits.

```sh
pip install unicorn numpy
python3 tools/gen_profile_vectors.py Xplane12/X-Plane.exe > tests/data/profile_stage.txt
cargo test --offline --test original_vectors
```

## Results

| Function | What it is | Cases | Result |
|---|---|---:|---|
| `0x1406ea0b0` | clamped linear interpolation helper ([AFL_REGIMES.md](AFL_REGIMES.md)) | 2000 | identical bits |
| `0x141a412c0` | angle correction, fixed-grid lookup, normalised angle, stall flag, active-stall noise | 1200 | identical bits |

For `0x141a412c0` the signature recovered from the disassembly is: `RCX` the table object (parameters at
`+0x04..+0x10`, Cl at `+0x14`, Cd at `+0xb58`, Cm at `+0x169c`, 721 floats each), `XMM1..XMM3` the noise x, y and
phase, then on the stack the retain flag, a diagnostics flag (kept 0 here, which skips the logging calls), the
angle, the multiplier, the divisor, and five output pointers: normalised angle, stall flag, Cl, Cd, Cm. The
cases cover three tables, angles from -200 to 200 degrees including the exact grid corners and zero, zero and
non-zero normalisation limits, zero and non-zero slope, retained and unretained stall with both initial states,
and times including 16777217 seconds. Of the 1200 cases, more than a hundred end in an active stall, so the
noise table and the double-precision time are exercised too.

This confirms, bit for bit, `src/aero.rs` (angle correction and lookup), `src/stall.rs` (normalised angle and
the hysteresis), `src/buffet.rs` (the noise perturbation and the six-scale sum) and the Cl scaling by the
divisor, as composed by `profile::evaluate_polar`. The earlier notes' statement that no comparison with the
running original had been done now holds only for the parts not listed here.

## Limits

- Only isolated functions on synthetic inputs. Agreement says nothing about how the engine produces the inputs
  (multiplier, divisor, regime parameter, noise coordinates, time).
- A function that touches engine state (global objects, virtual calls, the diagnostics stream) needs those
  pieces stubbed or its diagnostics path switched off; an unmapped access raises an error instead of being
  guessed.
- The emulator is not X-Plane: threading, the graphics driver and file access do not exist.
- Random vectors can miss rare edge cases; the cases deliberately include exact grid corners, zero bounds and
  the wrap boundaries but are not exhaustive.
