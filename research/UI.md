# Первый этап UI: Alt и Esc

Дата: 2026-10-07. Реализация: `src/ui.rs`, `src/ui.wgsl`, интеграция в `src/viewer.rs`.
Эталон: сборка из [BASELINE.md](BASELINE.md). Это функциональный прототип самостоятельного
интерфейса, не восстановленный оригинальный оконный движок.

## Основания

В извлечённой таблице клавиш EXE ([KEYMAP.md](KEYMAP.md), `assets/keymap/default_keys.tsv`):

- Esc → `sim/operation/show_menu`, описание `Show the in-sim menu.`
- обратная кавычка → `sim/operation/toggle_flight_config`.

В EXE присутствуют строки Resume Flight, New Flight, Start New Flight, Main Menu,
Go to Main Menu, Flight Configuration и Toggle the Main Menu screen.
Смещения в файле: Resume Flight `0x2605f38`, New Flight `0x2605cc6`,
Main Menu `0x24f428b`, Flight Configuration `0x2605ca8`, Toggle the Main Menu screen. `0x25c4008`.
Строки подтверждают названия, но не расположение элементов и не реализацию обработчиков.

[Официальное руководство X-Plane 12](https://x-plane.com/manuals/desktop/12/) описывает скрытую
панель меню, показ при наведении мыши к верху экрана и клавишу Esc для отображения меню.
Отдельное поведение Alt и различие двух экранов пока не подтверждены разбором обработчиков;
Alt реализован по запросу пользователя.

В переданном каталоге отсутствуют ресурсы оригинальных меню. Цвета, размеры, системный шрифт,
набор доступных пунктов, навигация клавиатурой и остановка физики на модальных страницах —
решения openXplane. Совпадение с оригинальным UI не заявляется.

## Техническая реализация

Меню растеризуется в RGBA с `ab_glyph`, загружается в sRGB-текстуру и смешивается с разрешённым
MSAA-кадром отдельным wgpu-проходом. Перерисовка интерфейса производится при изменении состояния,
размера, масштаба/выделения; телеметрия обновляется до десяти раз в секунду.
Hit testing использует физические пиксели, построенные при растеризации с учётом DPI.

События Esc/Alt перехватываются до flight key routing. При открытии меню Flight.release_held
снимает удерживаемые команды. Flight.advance продолжает обновлять часы при модальном окне,
но не шагает физику, поэтому после возврата не догоняет время, проведённое в меню.
Перезапуск использует существующий сброс Delete, а настройки меняют реально используемые
состояния паузы, клавиатурного штурвала, камеры и HUD. Плагинный пункт неактивен.

## Проверено и остаётся

- Шесть тестов переходов/захвата/выключенных действий/клавиатуры/DPI и растеризации.
- Просмотр PNG Main Menu, панели Alt и Settings.
- Нативный smoke Main Menu и Alt поверх KSEA/Cessna, Apple M4 Metal.
- Нет сравнения пикселей с оригиналом, запуска оригинальных UI handlers и ручного тестирования
  всей цепочки пользовательских событий. Layout не считается верифицированным портом.

Следующее: получить оригинальные UI resources и снимки обоих меню, определить входные обработчики,
восстановить структуру страниц и расширить каталог самолётов/аэропортов. Наличие названий в EXE не
заменяет этот разбор. Возможности текущего интерфейса: [docs/UI.md](../docs/UI.md).

## Продолжение: смена сессии (2026-10-07)

`flight_setup::FlightSetup` строит каталог ACF через существующий Install.find_acf и хранит
выбор самолёта и редактируемый идентификатор аэропорта. Меню запрашивает StartFlight; viewer
загружает новую `scene::airport_flight`, затем Renderer.replace_scene заменяет GPU-меши на том же
устройстве и в том же окне. Старые scene/Flight заменяются после успешной загрузки. При отказе
остаётся прежний полёт, а ошибка показывается в Flight Configuration.

Это самостоятельная логика на уже реализованных загрузчиках, не перенос оригинального UI handler.
Нет оригинальных карточек самолётов, аэропортового индекса/поиска, выбора полосы, погоды и веса.
ACF переключается циклически; аэропорт вводится кодом. Загрузка синхронная. В статическом viewer
нет контекста установки для такой смены; функция доступна в `fly`.

Добавлены тесты ограниченного ввода идентификатора и действий меню (смена ACF, ввод Airport,
неактивный запуск при пустом коде, StartFlight не закрывает страницу до результата).
Native reload smoke меняет самолёт и идентификатор через тот же обработчик загрузки, но
не имитирует аппаратные события пользователя. Порт оригинального оформления по-прежнему не проверен.
